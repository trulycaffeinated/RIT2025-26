# Buffers and FIFO

**Each buffer needs a controller**

Buffers are the most used data structure within Embedded system software - also implemented in hardware

Waterlines - too little data for buffer or too much data for buffer

As buffering increases...
Buffer size (physical) increases
Latency increases
Timing tolerance - the ability to manage time on both sides - increases
- The ability of your system to be tolerant of random timings
Memory size increases (expensive but ability to buffer is good)
Code Complexity increases

**Linear Buffers**
- Simplest type
- Single piece of linear contiguous memory
- controlled by pointers whose address increases linearly
- Problems
	- Lose data when full
	- fail to provide when empty
	- use high and low water marks (pointers) to prevent
	- Compare current pointer against water marks
- Not infinitely long
- Data must be kept in order it was placed
- Water marks have data above and below but free space doesn't lie in correct position

Double buffering
- Single buffering induces tremendous overhead managing pointers
- 2 buffers
	- one used for filling - capture/filling
	- one used for extracting - processing/emptying
