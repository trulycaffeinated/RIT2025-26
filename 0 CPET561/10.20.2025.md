# Memory Hierarchy & Cache
Further away from processor means higher latency (bigger delay) but bigger size.

**Memory items close to processor**
Data memory - data we just used, variables we want quick access too
Instruction memory - pull chunk of instructions and put in memory 

**Locality**
principle that makes hierarchy effective
Temporal locality - if an item is referenced it will tend to referenced again soon
	If you just used it, you'll use it again
spatial locality - if an item is referenced nearby items will be referenced soon
	If you used something in an area, you'll likely need more items in that area

**Hierarchy**
As you move further and further from processor, your access time grows (slows down)
Additionally the number of addresses you need to search increases (more items)

In terms of spatially, space around processor is expensive, so we use regions further from processor. We can store more things in this region in bigger chunks.

**Cache organization**
How do we determine where to put data in cache?
#### Direct-Mapped Cache
- Data is assigned a cache location based on its address
- Every memory location is exactly 1 location in cache
- Typical mapping is (Block Address) mod (Num Blocks)
![[Pasted image 20251020091227.png]]

Use lower bits to determine where data is in cache
*Problem* - How do you know if cache line 001 has data from memory 00001 or 11001?
- Need **TAG** field to hold missing address bits.
	- TAG + IDX -> Uniquely specific memory address

**Cache Thrashing** - When tags constantly fight for one cache location
	The two 001 tags are constantly trying to overwrite the same location

Cache hit - when the data the CPU wants is in the cache and can be used (+1 Speed)
Cache miss - when the data the CPU wants is not in the cache and needs to be pulled from memory (-1 speed)

Three types of cache misses #CheatSheetCPET 
**Compulsory** - Miss when first accessing a new address
	Nothing in there - so you get a miss - empty cache will only have misses
**Conflict** - Line is evicted upon access of an address whose index is already cached
	Solution
			Change Memory Layout
			Allow more lines for each index
**Capacity** - Line is evicted before it can be re-used because capacity of cache is exhausted

#### Fully Associative Cache
Data can be placed anywhere in cache
- Opposite of direct mapped cache

#### Set Associative Cache
Compromise between full associative and direct mapped. 
Data can be placed in a limited number of locations
If n locations then cache is called n-way set associative
- Direct mapped cache is a 1-way set associative
- 2 Way set associative is like 2 direct map caches

Increasing degree of associative-ness
- Lowers miss rate
- Increase hardware cost
- Increase hit time
