# Memory Hierarchy & Cache
Further away from processor means higher latency (bigger delay) but bigger size.

**Memory items close to processor**
Data memory - data we just used, variables we want quick access too
Instruction memory - pull chunk of instructions and put in memory 

**Locality**
principle that makes hierarchy effective
Temporal locality - if an item is referenced it will tend to referenced again soon
	If you just used it, you'll use it again
spatial locality - if an item is referenced nearby items will be referenced soon
	If you used something in an area, you'll likely need more items in that area

**Hierarchy**
As you move further and further from processor, your access time grows (slows down)
Additionally the number of addresses you need to search increases (more items)

In terms of spatially, space around processor is expensive, so we use regions further from processor. We can store more things in this region in bigger chunks.

**Cache organization**
How do we determine where to put data in cache?
Direct-Mapped Cache
- Data is assigned a cache location based on its address
- Every memory location is exactly 1 location in cache
- Typical mapping is (Block Address) mod (Num Blocks)
