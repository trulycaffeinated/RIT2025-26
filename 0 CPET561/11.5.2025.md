# Direct Memory Access (DMA)

Mechanism for transferring data directly to/from memory and/or IO without involving processor
Requires the use of a DMAC (DMA Controller)

**Programmed I/O** - uses input and output instructions (processor) to transfer data between devices
- Data transfer can be under program or interrupt control
Advantage 
- Simple to implement
Disadvantage
- Processor is tied up transferring data
- Poor utilization of processor

**DMAC**
- Special hardware controller for data transfer (offloads work from processor)
- Takes place of processor in data transfers
- Performs all bus operations
Advantages
- Allows data transfer w/o processor
- Increases system performance
Disadvantages
- More complex
- requires specialized hardware

Processor must provide the following to the DMAC
- Source address
- Destination address
- start indicator (bit)
- number of bytes being transferred

1. Program the DMAC
2. Start the transfer
3. Request the bus (processor may be using it)
4. Issue the addresses
5. Transfer the data
6. Update the addresses
7. Update the processor (interrupt)

#### Transfer Modes
**Burst Mode**
- DMAC takes bust for entire transfer period
- $\mu$P has to wait
- Could be a problem if $\mu$P gets an interrupt

**Cycle Steal Mode** 
- Transfer only 1 byte or word per mastership
- $\mu$P free to use bus during other cycles
	- Don't want processor taking bus for long periods

**Transparent**
- Processor makes idle cycles known
- DMAC claims bus only when processor does not need it
- Good for Processor as it never waits
- DMAC could end up waiting if there are long delays between idles
- Requires additional interface signals between processor and DMAC

# Clk domain crossing

Two (or more) clocks of either the same or different frequencies that are not synced, data that needs to transfer from device A with clk A to device B with clk B crosses the **clk domain**

$t_{su}$ - Setup Time
$t_h$ - Hold Time
$t_Q$ - Clk to Q

Can use double flip flop setup to help deal with metastability events, however these events are always going to occur as the clocks are not perfect. Additionally, interrupts will violate setup and hold time. 

TLDR; Setup time and Hold times will frequently be violated by something - deal with it

Data as a bus when moving from one location to another will have mismatched trace timings. Flip-Flops are not all identically placed.

TLDR; Single bit is easier to move than a bus

Nyquist theorem applies to clk domain crossing *roughly*

Going from 10 MHz to 50 MHz is easy - nyquist
Going from 50 MHz to 10 MHz is hard - need to pulse stretch it to be caught
